## 3. Traceability — measured, not claimed

The instruction was that every result be traceable to an artifact. That is easy to
assert and easy to get wrong, so it is tested three ways.

### 3.1 Numeric traceability

`scripts/verify_paper_claims.py` reads **77 values out of the experiment
artifacts**, formats each the way the paper prints it, and requires that string to
appear in the text. The checks read the artifact first and the paper second, so a
wrong number in the paper cannot make its own check pass.

```
Checking 77 numeric claims in research_paper.md against the artifacts
All 77 artifact values appear verbatim in the paper.
```

## 4. No unsupported claims — enforced by test

The instruction was explicit: do not say "engagement increased by X%" unless the
dataset supports it. **[Design decision]** A numeric check cannot catch this,
because the violation is a *sentence*, not a number. `tests/test_paper.py`
therefore greps for the claim shapes themselves:

| Forbidden pattern | Why |
| --- | --- |
| `engagement (increased\|improved\|rose\|grew)` | Causal claim; no engagement measure exists |
| `boosted (engagement\|retention\|completion)` | Same |
| `resulted in a N%` / `drove a N%` | Causal attribution |
| `significantly outperform` | No method is significantly better than random |
| `statistically significant improvement` | Same |

**[Verified]** The patterns were tested against six synthetic violating sentences
and caught all six, while a correctly-phrased sentence ("the impact proxy reached
1.084 against random ranking 1.046 on the same measure") was not flagged. A test
that cannot fail proves nothing — the same principle Phase 6A established.

Two further tests enforce the pairing rules the project committed to:

- **The impact proxy never appears without its reference.** Any line containing
  1.084 must also contain 1.046.
- **The deployed method's NDCG is never quoted in prose without random's.**

## 7. A correction found while writing

**[Finding]** Assembling §16.1 from the artifacts revealed that the Gini column in
the Phase 4 decision matrix (`research/ARCHITECTURE_FREEZE.md`) carried
**validation**-window values while every other column in the same table came from
the **test** window — a mixed-provenance row.

No decision changes: Gini was never a selection criterion, and the ordering is
materially the same. But a table whose columns come from different evaluation
windows is wrong regardless of whether it changed an outcome. The freeze has been
corrected to test-window values with the correction recorded in place rather than
silently amended, and the paper uses test-window values throughout.

**[Interpretation]** This is the third document-level inconsistency the late phases
have caught (after the stale prediction table in Phase 4 and the representation
table in Phase 5B). All three were found by rebuilding a table from its artifact
instead of copying it forward — which is the practice worth keeping.
